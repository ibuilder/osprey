Code signing policy

How Osprey's Windows binaries are signed, who can approve a signature, and what the software does with your data.

Free code signing provided by SignPath.io, certificate by SignPath Foundation.

What is signed

Windows release artifacts built from this repository's public source by its release workflow on GitHub Actions (release.yml):

  • the installers: Osprey_<version>_x64-setup.exe and Osprey_<version>_x64_en-US.msi
  • the bundled backend executable, osprey-backend.exe, which ships inside those installers

Nothing built on a developer's machine is signed. Third-party libraries bundled alongside the backend (for example the Python runtime) are not re-signed by this project. macOS and Linux builds are not covered by this certificate.

Because the certificate is issued to SignPath Foundation, Windows shows SignPath Foundation as the publisher of a signed Osprey installer.

Privacy policy

This program will not transfer any information to other networked systems unless specifically requested by the user or the person installing or operating it.

In practice that means Osprey contacts only what its operator configures:

  • the data sources a user explicitly connects (for example Microsoft 365, Google, or Procore), using the account the user authorizes;
  • an AI provider, only if one is configured — the default provider runs entirely offline;
  • an OpenTelemetry collector, only if the operator enables it and supplies the address.

Osprey sends no usage data, analytics, or crash reports to its maintainers.

Verifying a download

On Windows, open the installer's Properties → Digital Signatures tab. Every release also publishes SHA256SUMS.txt and signed build provenance, which can be checked with gh attestation verify <file> --repo ibuilder/osprey.
